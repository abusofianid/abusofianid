# GitHub Stats Cards

This directory contains the generator and SVG cards used to display all-time GitHub statistics and the most-used programming languages on a GitHub profile.

## What gets generated

The workflow generates four theme-aware SVG files:

- `github-stats-dark.svg` — all-time statistics for dark mode.
- `github-stats-light.svg` — all-time statistics for light mode.
- `github-top-langs-dark.svg` — most-used languages for dark mode.
- `github-top-langs-light.svg` — most-used languages for light mode.

The cards are generated by `update_stats.py` and committed to this repository by GitHub Actions. No Vercel deployment is required.

## Requirements

- A GitHub repository where you can add workflow files and repository/environment secrets.
- A GitHub Personal Access Token (fine-grained token is recommended) with read access to the repositories and data you want to include.
- The workflow's built-in `GITHUB_TOKEN` permission `contents: write`, already declared in `.github/workflows/update-stats.yml`, so Actions can commit updated SVG files.

For private repositories, include those repositories in the token's repository access scope and grant the read-only repository permissions needed by the APIs:
- **Contents: Read-only** — read commit history.
- **Issues: Read-only** — count authored issues.
- **Pull requests: Read-only** — count authored pull requests.

Only grant access to repositories and data you intend to include. Never commit the token or print its value in logs.

## Setup

### 1. Create a Personal Access Token

1. Open GitHub **Settings → Developer settings → Personal access tokens → Fine-grained tokens**.
2. Choose **Generate new token** and give it a descriptive name, such as `GitHub Stats Generator`.
3. Choose the resource owner that owns the repositories you want to read.
4. Under repository access, select all repositories that should be included. If private repositories should count, make sure they are selected.
5. Grant the read-only permissions listed above.
6. Generate the token and copy it securely. GitHub only shows the token value at creation time.

The exact repositories and permissions available depend on your account and organization policies.

### 2. Add the token as an environment secret

This workflow uses a GitHub Environment named `GH_STATS_TOKEN` and expects an environment secret with the same name.

1. In the repository, open **Settings → Environments**.
2. Create or open the environment named `GH_STATS_TOKEN`.
3. Under that environment's secrets, choose **Add secret**.
4. Set the name to `GH_STATS_TOKEN` and paste the token value as the secret.
5. Save the secret.

Do not put the token in the source code, README, workflow YAML, or a commit.

### 3. Run the workflow

1. Open the repository's **Actions** tab.
2. Select **Update GitHub Stats**.
3. Select **Run workflow**, choose the `main` branch if prompted, and start the run.
4. When the run completes successfully, the workflow commits changed SVG cards to `github-stats/`.

The workflow also runs automatically every day at **00:00 UTC (08:00 WITA)** and when its workflow definition or Python generator changes on `main`.

### 4. Display the cards in a profile README

Copy the following markup into the README where you want the cards to appear. The `picture` element lets GitHub select the SVG matching the viewer's light or dark theme.

```html
<picture>
  <source media="(prefers-color-scheme: dark)" srcset="./github-stats/github-stats-dark.svg" />
  <source media="(prefers-color-scheme: light)" srcset="./github-stats/github-stats-light.svg" />
  <img src="./github-stats/github-stats-dark.svg" alt="GitHub all-time statistics" />
</picture>

<picture>
  <source media="(prefers-color-scheme: dark)" srcset="./github-stats/github-top-langs-dark.svg" />
  <source media="(prefers-color-scheme: light)" srcset="./github-stats/github-top-langs-light.svg" />
  <img src="./github-stats/github-top-langs-dark.svg" alt="Most used programming languages" />
</picture>
```

These relative paths work when the SVG files and README are in the same repository. If you use the cards in a different repository, use URLs pointing to the generated SVG files in the stats repository.

## What each statistic means

The main card contains six metrics:

1. **Total Contributions** — contribution-calendar totals summed across calendar years starting in 2008.
2. **Total Commits** — distinct commits attributed to the account on the default branches of accessible repositories owned by the account. It is not a count of every commit on every branch or every repository on GitHub.
3. **Total Issues Opened** — unique issues authored by the account across accessible repositories, in any state. Pull requests are excluded.
4. **Total Pull Requests** — unique pull requests authored by the account across accessible repositories, including open, closed without merging, and merged PRs. Each PR is counted once.
5. **Total Stars Earned** — the sum of stars on accessible repositories owned by the account.
6. **Repositories Contributed To** — the number of repositories returned by GitHub's `repositoriesContributedTo` connection for the account.

The languages card shows up to six languages aggregated from GitHub-reported language bytes across accessible repositories owned by the account. Its language segments retain their language-specific colors.

## Files

- `update_stats.py` — queries GitHub GraphQL and REST APIs and writes the four SVG cards.
- `github-stats-dark.svg`, `github-stats-light.svg` — main statistics cards.
- `github-top-langs-dark.svg`, `github-top-langs-light.svg` — language cards.
- `guide.json` — concise machine-readable metadata and a link to this tutorial.
- `.github/workflows/update-stats.yml` — schedules and runs generation.
